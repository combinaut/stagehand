# Agent Guidelines

## Git Commit Conventions

- Write commit messages without hardcoded line wrapping.
- In commit messages, wrap filenames, code identifiers, and commands in backticks.
- Include a concise commit title, aiming for a maximum 50 characters, that gives an idea of what the commit is about
- For a bugfix the message should start with an explanation of the symptoms, then in a second paragraph explain the root cause, then follow that with a detail explanation of the solution, and finally if any other solutions were considered explain why they were not chosen. Do not use vague wording like "there was a regression and this fixed it".
- Prefer focused commits that include only files relevant to the requested change.
